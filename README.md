# PDF 双语翻译器

用 DeepSeek（或任意 OpenAI 兼容大模型）翻译 PDF，**保留原排版**、**跳过图片和表格**、
并额外输出一份**双语对照版**。

```
┌─────────────────────────┐        ┌─────────────────────────┬─────────────────────────┐
│  Retrieval-augmented    │        │  Retrieval-augmented    │  检索增强生成（RAG）    │
│  generation (RAG) has   │  ───▶  │  generation (RAG) has   │  已经成为让大语言模型   │
│  become a standard...   │        │  become a standard...   │  对接外部知识的通用...  │
│                         │        │                         │                         │
│      [ 插图 ]           │        │      [ 插图 ]           │      [ 插图 ]           │
└─────────────────────────┘        └─────────────────────────┴─────────────────────────┘
        原始 PDF                      双语对照版：左=原文，右=译文（位置逐段对齐）
```

## 核心特性

| 能力 | 说明 |
| --- | --- |
| **保留原排版** | 逐段读取原文的坐标、字号、颜色、加粗、对齐方式，译文写回同一位置；放不下时自动缩小字号，仍放不下则向下扩展空白区，绝不丢字。 |
| **不翻译图片与表格** | 自动识别图片区域与表格区域（基于矢量线条分析），这些区域内的文字原样保留，插图、表格线、图表标签都不会被动。 |
| **双语对照版** | 输出左右分栏（或上下分栏）的对照 PDF：一侧是完整原文，另一侧是同一版面的译文，段落位置严格对齐，方便逐段校对。 |
| **接入任意大模型** | 内置 DeepSeek / OpenAI / Kimi / 通义千问 / 智谱 GLM / 硅基流动 / 本地 Ollama 七种预设，也可以填任意 OpenAI 兼容端点。 |
| **省 token** | 多个段落打包成一次请求；译文按内容哈希缓存到本地 SQLite，中断后重跑不重复计费。 |
| **抗跑偏** | 模型返回条数不对时自动把该批**二分拆分重试**，最坏降级到逐条翻译，保证「段落 ↔ 译文」永不错位。 |
| **术语表** | 支持 JSON / CSV / TXT 术语表，注入提示词强制生效，并在本地做兜底替换。 |
| **大文件友好** | 多线程并发请求、失败指数退避重试、可指定页码范围只翻译其中几章。 |

## 三分钟上手

### 1. 安装依赖

**双击 `安装依赖.bat`** —— 它会自动在常见位置找到 Python，并安装 PyMuPDF 与 requests。

> 需要 Python 3.10 或更高版本（本机已装 3.12）。
> 从 [python.org](https://www.python.org/downloads/) 安装时请勾选 **Add python.exe to PATH**。
>
> ⚠️ 如果你在命令行敲 `python` 却弹出了「微软应用商店」，说明系统里只有 Windows 的
> 占位程序，并没有真正的 Python。这种情况下 `python -m pip ...` 之类的命令都不能用，
> 请直接双击 `安装依赖.bat`（它内部按绝对路径查找，不依赖 PATH）。

也可以手动指定路径执行：

```bat
"%LOCALAPPDATA%\Programs\Python\Python312\python.exe" -m pip install -r requirements.txt
```

如果下载慢，换国内镜像：

```bat
"...\python.exe" -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 2. 启动界面

双击 **`启动界面.bat`**（或 `run_gui.pyw`）。

### 3. 填 Key、选文件、点开始

1. 「服务商」选 **DeepSeek**，粘贴 API Key（[申请地址](https://platform.deepseek.com/api_keys)）
2. 点「测试连接」确认能通（结果会显示在「③ 运行日志」页）
3. 切回「① 文件与引擎」，「添加文件…」选择要翻译的 PDF
4. 在「② 翻译设置」里确认输出目录和输出模式（默认两个版本都出）
5. 点右下角 **▶ 开始翻译**（这个按钮固定在窗口底部，任何标签页都能点到）

完成后点「打开输出目录」，会看到两个文件：

```
paper_译文.pdf         ← 译文替换版：版式和原文一致，正文变成中文
paper_双语对照.pdf      ← 双语对照版：左英文右中文，逐段对齐
```

### ① 文件与引擎

- **文件列表**：支持多选、支持整个文件夹；双击某一项可在资源管理器里定位该文件
- **服务商**：选一个预设就自动填好 Base URL 和模型名
- **API Key**：默认「记住」（存在 `%APPDATA%\pdf-translator\settings.json`），取消勾选则不落盘
- **测试连接**：真的发一次请求验证 Key 是否可用，报错信息会直接显示在日志页

### ② 翻译设置

| 选项 | 作用 |
| --- | --- |
| 目标语言 | 12 种常用语言；译文会自动切换到合适的中日韩字体 |
| 页码范围 | 如 `1-5,8,10-`，留空表示全部 |
| 并发请求数 | 默认 4；服务商限流严格时调小，额度充足时可调到 8 |
| 译文最小字号 | 默认 0.62，即译文最多缩到原字号的 62%，再小就向下扩展 |
| 术语表文件 | 见下方[术语表](#术语表) |
| 附加要求 | 追加的自定义翻译指令，例如「使用学术书面语」「人名保留英文」 |
| 翻译表格内文字 | 默认**关闭**（表格整体跳过） |
| 翻译图表标注与公式 | 默认**关闭**（图表内的坐标轴/图例/子图标题、以及独立公式都原样保留） |
| 翻译页眉页脚 | 默认开启；跨页重复出现的页眉会自动识别 |
| 允许译文向下扩展 | 默认开启，避免长译文被截断 |
| 使用译文缓存 | 默认开启，重跑同一文件几乎不花 token |
| 输出目录 | 留空则输出到源文件同目录 |
| 输出模式 | 「译文替换版」和「双语对照版」可任选，默认两个都出 |

### ③ 运行日志

点「开始翻译」或「仅扫描统计」会自动切到这一页。日志里会写明：读了多少页、多少文字块、
跳过了多少图片/表格区域、打包成多少次请求、用了多少 token、每个输出文件的完整路径。

「仅扫描统计」不调用 API，可以先用它看看 PDF 里有多少字、有多少图片表格，估算成本。

## 命令行完整用法

```bat
translate-pdf.bat <文件...> [选项]
```

### 最常用

```bat
:: 用 DeepSeek 翻译，两个版本都输出
translate-pdf.bat paper.pdf --api-key sk-xxxxxxxx

:: 只输出双语对照版，只翻前 10 页，8 并发
translate-pdf.bat book.pdf -m bilingual --pages 1-10 -c 8

:: 整个目录批量翻译
translate-pdf.bat D:\papers\*.pdf -o D:\papers\译文 --to zh

:: 用本地 Ollama，完全离线
translate-pdf.bat doc.pdf --engine ollama --model qwen2.5:7b

:: 先看看有多少内容、要花多少钱
translate-pdf.bat paper.pdf --dry-run

:: 只测试 API Key 通不通
translate-pdf.bat --test --api-key sk-xxxxxxxx
```

## 术语表

支持三种格式，`--glossary` 或界面里选择即可。

**JSON**（推荐，适合专业文档）：

```json
{
  "transformer": "变换器",
  "retrieval-augmented generation": "检索增强生成",
  "attention mechanism": "注意力机制",
  "fine-tuning": "微调"
}
```

**纯文本**（每行一条，`=` 或制表符分隔）：

```
transformer = 变换器
retrieval-augmented generation = 检索增强生成
```

**CSV**：

```csv
source,target
transformer,变换器
embedding,嵌入
```

术语表有双重保险：先写进提示词要求模型遵守，翻译完再在本地检查一遍、把漏掉的词强制替换。

## 工作原理

```
 ┌──────────┐   ┌───────────┐   ┌──────────────┐   ┌───────────┐
 │ ① 解析   │──▶│ ② 过滤    │──▶│ ③ 批量翻译   │──▶│ ④ 重建    │
 │ 文字块+  │   │ 图片/表格 │   │ 并发+缓存+   │   │ 原位替换  │
 │ 版面信息 │   │ 区域跳过  │   │ 二分降级     │   │ 双语分栏  │
 └──────────┘   └───────────┘   └──────────────┘   └───────────┘
```

**① 解析**：用 PyMuPDF 的 `get_text("dict")` 拿到每个 span 的 bbox、字号、字体 flags、
颜色，再把同一段落的行合并回自然语言（处理英文断词连字符、中英混排空格）。

解析阶段还做几件容易被忽略、但对版式还原很关键的事：

- **合并 bbox 互相重叠的文本块**。PyMuPDF 会把同一段文字**按字体拆成多个块**——
  正文一个块、行内数学公式（CambriaMath 之类）另一个块——但每个块的 bbox 都覆盖整段。
  不合并的话它们会被当成互不相干的段落各自翻译、各自清除原文、各自写入，中文写上去
  之后没被删掉的公式符号还留在原地，就叠字了。
- **把 Unicode 数学字母折回普通字母**（`𝑛`→`n`、`𝒖`→`u`、`𝟏`→`1`）。这些字符只是
  数学斜体的一种编码，中文字体不含它们的字形，写进译文会缺字、宽度也量不准；
  送进提示词还会让模型误以为整段都是公式而拒绝翻译。
- **按样式重新切分文本块**。PyMuPDF 经常把「小节标题 + 紧跟的正文段落」塞进同一个
  文本块（例如 `1 Introduction` 和它下面那段话）。如果整块一起翻译，标题就会被并进
  正文、字号也被统一掉。这里按行主字号与粗体状态的变化把它重新切开。
  判定切分点时会检查「这一组行是否都明显短于本块最宽的行」——因为标题总是短的，
  而有些正文段落整段用粗体排印，光看字体属性会误判。
- **推断对齐方式**。多行块看各行边界；单行块看它在「版心」（本页所有文字块的外接范围）
  里的相对位置。判定居中必须**左右两侧都有明显留白且留白大致相等** —— 只比中心位置
  是不够的：像 `CCS Concepts: …` 这种满版心的正文行，中心本来就贴着版心中心，
  会被误判成居中。
- **补回 span 之间丢失的空格**。PyMuPDF 在 span 边界常常吞掉空格
  （`We let 𝑛` + `and` → `We let 𝑛and`），按两个 span 的坐标空隙补回来，否则会污染译文。

**② 过滤**：
- 图片区域来自 PDF 的图片对象及其在页面上的实际矩形，位置可靠 —— 压在图片里的说明文字一律不翻
- 表格区域来自 `find_tables(strategy="lines_strict")` 的线条分析；改用严格模式是为了
  避免把柱状图/折线图误判成表格
- **图表区域来自 `cluster_drawings()` 的图形聚类**。柱状图、折线图、结构示意图大多是用
  线条画的、不是嵌入图片，靠图片对象完全识别不到，里面的坐标轴标题、图例、子图标题就会
  被当成正文翻译。聚类出的矩形外扩 4pt 后，与之重叠超过 20% 的文字块一律保持原样。
  实测这个判据很干净：图内标签重叠 21%~100%，而正文段落和图题都是 **0%**。
- **独立公式整块保留**。区分「整块公式」和「正文里夹了公式」靠的是**有没有正常的英文
  单词**：`φ0: u4 u0 u5 u1 u3 u2` 只有单字母变量和符号，凑不出 3 个字母以上的词；
  而 `Practical cost estimation (ci,li). Since deriving…` 单词一堆，照常翻译。
- **图题/表题豁免表格判定**。`Fig. 6. …` 这类图题紧贴着图，而图又常被误判成表格，
  于是整块被丢掉——同一篇论文里就会出现有的图题翻译了、有的没翻译。图题恰恰最该翻译，
  所以对表格区域完全豁免（对图片和图表区域不豁免）。
- 与跳过区域重叠超过阈值的文字块直接跳过（图片 35%、表格 30%、图表 20%）
- 被跳过的文字块会登记为**障碍物**，旁边块的译文向下扩展时必须绕开，否则会压上去叠字
- 竖排/旋转文字暂不处理，避免破坏版面
- 纯数字、纯符号、纯 URL 的内容不送翻译，省 token
- 上下边距带里跨页重复出现的短文本被标记为页眉页脚（可开关）

> 想连图表标注和公式一起翻译？界面里勾「翻译图表标注与公式」，
> 或命令行加 `--translate-figures`。

**③ 翻译**：连续段落打包成 JSON 数组，一次请求翻译多段。返回结果条数不符就二分拆分重试。
失败时保留原文而不是丢弃，保证文档完整性。所有译文按哈希缓存。

**④ 重建**：

*替换版*
1. 对每个文字块的矩形做 redaction，真正删掉原文（`images=None` 保留图片，
   `graphics=None` 保留线条和表格框线）
2. **盖掉落在待重写块里的细横线**（下划线、分数线、强调线）。它们是独立矢量对象，
   不会跟着译文走，译文一重排就错位。只处理**完全落在**块内部的线，所以表格线、
   图片边框、页眉分隔线都不受影响。覆盖用的是从页面采样的纸张底色，非白底也不留白道子
3. 自研的轻量排版引擎按原宽度断行（CJK 逐字断、拉丁按词断、带避头尾规则）
4. 从原字号开始试排，放不下就按 0.25pt 步进缩小，直到 `min_font_scale` 下限
5. 仍放不下则向下扩展，扩展边界自动避开下方图片、表格和下一个文字块
6. 写入前按字体能力规范化字符：目标字体渲染不出来的字符换成它的等价写法
   （`𝑛`→`n`、`✓`→`√`），否则测量与定位都会算错
7. 用 `TextWriter` 精确写入，还原颜色、对齐方式；粗体使用真正的粗体字体文件

*双语版*
1. 新建页面：左右分栏时宽度 = 原文宽 × 2 + 间隙；上下分栏时高度 = 原文高 × 2 + 间隙
2. 两侧都用 `show_pdf_page` 贴入原始页面，图片、表格、矢量图原样保留
3. 右栏（或下栏）清除原文文字后写入译文，坐标做整体偏移
4. 页面带旋转（`/Rotate`）时自动退化为「一页原文 + 一页译文」，确保内容不丢

**字体**：译文是中文/日文/韩文时自动从系统里挑合适的字体（微软雅黑、黑体、宋体、
Meiryo、Malgun 等），并做子集化嵌入，文件不会无谓变大；纯拉丁译文则使用 PDF 内置的
Helvetica / Times，不嵌入任何字体。系统里找不到中文字体时回退到 PyMuPDF 内置的
CJK 字体，保证一定能出结果。

## 常见问题

**Q：翻译出来是空白 / 提示「没有文字层」？**
说明这是扫描版 PDF，页面里只有图片没有文字。需要先用 OCR 工具（如
[OCRmyPDF](https://github.com/ocrmypdf/OCRmyPDF)、ABBYY、Adobe Acrobat 的「识别文本」）
加上文字层，再用本工具翻译。

**Q：译文比原文长，会不会被截断？**
不会。会自动缩小字号、向下扩展区域。如果连最小字号都放不下，日志里会给出提示，
改用双语对照版就没有这个限制。

**Q：表格里的文字没翻译。**
这是默认行为，因为机器翻译表格容易破坏单元格结构。需要的话加 `--translate-tables`。

**Q：报 401 / API Key 被拒绝。**
检查 Key 有没有复制全、账户有没有余额、模型名是否拼错。界面上点「测试连接」会给出
更具体的错误信息。

**Q：报 429 限流。**
把「并发请求数」调到 2 或 1，工具本身也带指数退避重试。

**Q：译文位置有偏移 / 出现重影。**
把「清除原文方式」换成 `cover`（命令行 `--replace-mode cover`）。极少数 PDF 里文字
外框比实际字形大很多，redact 会留下残影，白底遮盖反而更干净。

**Q：能翻译多大的 PDF？**
几百页没问题。建议先用 `--pages` 试翻几页确认效果，再跑全书。有缓存，中断后重跑
不会重复计费。

**Q：支持 macOS / Linux 吗？**
核心逻辑是跨平台的，把 `install.bat` 换成 `python -m pip install -r requirements.txt`
即可。字体探测会自动去 `/usr/share/fonts` 等目录找中文字体。

## 第一次使用：先验证，再花钱

### 第 0 步：不花一分钱验证排版（可选，推荐）

用内置的 Mock 翻译服务跑一遍，确认排版符合预期后再去充钱：

```bat
:: 窗口 A：启动假翻译服务
python tools\mock_server.py --port 8123

:: 窗口 B：翻译样例文件
translate-pdf.bat samples\sample_en.pdf --engine custom ^
    --base-url http://127.0.0.1:8123/v1 --model mock --api-key mock ^
    --no-cache -o demo_output

:: 把结果渲染成图片，直接看排版
python tools\preview.py demo_output\sample_en_译文.pdf --dpi 110
python tools\preview.py demo_output\sample_en_双语对照.pdf --dpi 110
```

Mock 返回的中文内容是没有意义的占位文本，但**版式、字号缩放、双语分栏、图片表格保留**
的行为和真实 API 完全一致，很适合先确认「排版引擎」是否合你的意。

### 第 1 步：用真实 API 验证一小段

```bat
:: 只翻第 1 页，确认译文质量和排版
translate-pdf.bat 你的文件.pdf --api-key sk-xxxxxxxx --pages 1

:: 看一眼花了多少 token
translate-pdf.bat 你的文件.pdf --api-key sk-xxxxxxxx --dry-run
```

确认没问题后再去掉 `--pages` 跑全书。译文有缓存，重跑不会重复计费。

## 已知限制

| 情况 | 表现 | 说明 |
| --- | --- | --- |
| 扫描版 PDF（无文字层） | 提示「没有文字层」，直接复制原文件 | 需要先 OCR；工具会在日志里明确告知 |
| 竖排 / 局部旋转的文字 | 保留原文，不翻译，日志里给出数量 | 写入方向难以可靠还原，保留原文比乱排更安全 |
| 矢量插图（非位图）内的标注 | **已默认跳过**，保持原文 | 靠 `cluster_drawings()` 图形聚类识别；若个别标签仍被翻到，用 `--translate-figures` 的反面即默认行为 |
| 独立公式 | **已默认跳过**，保持原文 | 含少量变量的公式行会被识别；勾选「翻译图表标注与公式」可关闭 |
| 花体 / 手写体 / 艺术字标题 | 译文用标准字体，观感与原文不同 | 只继承字号、颜色、粗体与对齐，不继承特殊字形 |
| 多栏排版（学术论文双栏） | 逐块翻译，位置准确；单行块不会跨栏借用留白 | 横向扩展会自动避开同栏内的其他块 |
| 行内混排样式 | 只保留整块的样式，行内局部加粗/斜体不单独还原 | 例如「**Comparison of Algorithms:** 我们首先…」整行统一取主导样式 |
| 译文明显长于原文的段落 | 会自动缩小字号（最低到 5pt），极端情况才允许略微溢出 | 优先保证不与下一段重叠；日志里会统计有多少段落被缩过 |
| 表格文字 | 默认整体跳过（`--translate-tables` 可开启） | 强行翻译表格容易破坏单元格结构 |
| 每页文字超过数万字符 | 较慢 | 建议用 `--pages` 分批，缓存保证不重复计费 |

### 离线自检

不联网、不需要 API Key，验证整条流水线（含排版效果）：

```bat
python tests\test_offline.py      :: 端到端 36 项
python tests\test_gui_smoke.py    :: 图形界面 31 项
```

`test_offline.py` 会自动生成样例 PDF、启动 Mock 翻译服务，检查：

- 版面提取：文字块、图片区域、表格区域、页眉页脚标记、对齐方式推断
- 翻译流程：批量打包、JSON 解析、缓存命中、模型返回条数不符时二分降级
- 译文替换版：原文被替换、图片表格完好、页数不变、无文字溢出页面
- 双语对照版：页面加宽、左栏纯净原文、右栏译文、表格保留

`test_gui_smoke.py` 会隐藏地建一个窗口，验证控件齐备、引擎预设联动、设置读写往返。
